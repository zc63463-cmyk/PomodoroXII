## 本轮需要确认的产品判断

- Cycle 是否准确体现“注意力窗口”，而不是传统 Sprint 压力；
- Committed / Planned / Stretch 三档角色是否容易理解；
- 区间容量的稳健、无缓冲、有压力、明确超载是否足够清楚；
- 周预算 → Project → Cycle 的容量分配是否值得首版维护成本；
- 轻量基线和变更记录是否帮助校准而不会形成追责感；
- 周期结束的人工结转与复盘是否可接受；
- 数学模型只读容量投影、不反写计划的边界是否正确。

## 原型交互

- 切换“计划工作面 / 变化记录 / 周期复盘”；
- 切换团队汇总、蒋指导、林同学的容量；
- 打开容量调整抽屉；
- 加入临时 urgent 工作，观察整体计划从“有压力”变成“明确超载”；
- 在复盘队列中查看未完成项的结转方式和新角色选择。

## 审查结论选项

- **批准**：冻结为 Cycle v1.0 产品基线，并进入工程实施增量计划；
- **有条件批准**：列出必须修订项，修订后冻结；
- **退回讨论**：指出产品语义冲突，回到对应章节逐项确认。

## 当前边界

本审查包不包含 AI 自动排期、Cycle Goal、Story Points、成员绩效、日历自动扣减、Orbit 数学权重或风险视觉映射。
