# 工程实施阶段 Agent / 专家协作建议

> 结论：需要，但不需要用户额外手动叫一大群 Agent。当前实施计划已并行使用四个专家视角完成首轮审查。进入实际工程后，建议按门禁叫专家，不要长期堆叠角色。

## 1. 已参与本计划的专家视角

1. **目标架构专家**：后台单写者、多窗口、模块化单体、依赖方向和架构门禁；
2. **本地优先/数据专家**：SQLite、事务事件、乐观并发、编号、时区、备份与恢复；
3. **旧代码迁移审计专家**：Phase14C 白名单、黑名单和 clean-room 隔离；
4. **产品技术项目经理**：纵向切片、用户可见交付、退出标准和范围控制。

这些视角已经足够支撑“工程实施计划”阶段，不需要现在再邀请更多 Agent 才能继续。详细问题与修订证据保存在本轮任务记录和实施计划的风险/ADR/迁移章节中；进入工程后，每次专项审查应另存可追溯报告，而不是只保留聊天结论。

## 2. 后续推荐的按需专家

### A. 桌面壳 / 系统架构专家

**介入时间**：Gate 0。

**任务**：对 Tauri v2 与 Electron 做同一测试清单的 Spike，验证后台驻留、透明置顶多窗口、IPC 隔离、单实例、安装升级和诊断能力。

**必须产出**：ADR-001、能力对照表、可运行最小验证和明确失败证据。

**不要做**：顺便实现正式 WorkItem UI。

### B. 数据库 / 本地优先专家

**介入时间**：E-03 开始前与完成后。

**任务**：审查 schema、事务边界、expectedVersion、commandId 幂等、displayKey、迁移、WAL、备份恢复和故障注入。

**必须产出**：E-03 前冻结 ADR-004、ADR-005、ADR-006、ADR-009；ADR-007/008 在 E-07 前冻结。另需恢复演练结果、离线重放、并发和迁移测试报告。

### C. DDD / 架构审查专家

**介入时间**：Phase 0、Phase 3、Phase 5、P0 发布前。

**任务**：检查 Domain/Application/Projection/Infrastructure 依赖方向，防止 Repository 业务化、UI 直连存储和第二事实源。

**必须产出**：模块依赖图、违规引用清单、修复建议。

### D. 测试与可靠性专家

**介入时间**：每个纵向 Phase 结束。

**任务**：属性测试、故障注入、迁移、崩溃恢复、投影重建、并发和桌面 E2E。

**必须产出**：退出门禁报告；不能只报“测试通过”，还要覆盖失败模式。

### E. 可访问性 / 交互质量专家

**介入时间**：Phase 1 原型、Phase 6 发布门禁。

**任务**：键盘、焦点恢复、屏幕阅读器、200% 文本、44px 触控、信号非颜色表达、降低动态效果。

**必须产出**：核心流程 WCAG 2.1 AA 检查报告。

### F. 产品验收专家

**介入时间**：每个纵向 Phase 的演示评审。

**任务**：按产品 Given/When/Then 验收，检查是否出现范围蔓延或工程实现改写产品语义。

**必须产出**：批准 / 有条件批准 / 退回，以及明确修订项。

## 3. 暂时不建议邀请的角色

- 云架构/微服务专家：P0 无云同步和服务端；
- AI Agent 编排专家：P0 明确不做 AI 自动排期；
- 数据科学/风险模型专家：Orbit 数学权重不属于当前范围；
- 企业权限专家：多人权限和组织架构后置；
- 移动端专家：当前只保证窄屏详情，不做完整移动应用。

过早邀请这些角色，容易把已收敛的 WorkItem P0 再次扩成大平台。

## 4. 建议协作方式

```text
主 Agent：维护产品基线、实施计划与最终综合判断
    ↓
专项 Agent：只回答一个边界明确的问题
    ↓
交叉审查 Agent：找矛盾和失败模式，不直接改方向
    ↓
主 Agent：核对文件和测试后合并结论
    ↓
产品负责人：在阶段门选择批准/有条件批准/退回
```

建议一次并行 2~4 个独立专项，不要让多个 Agent 同时修改同一文件。所有专家结论都必须回到已批准的 v1.0 产品基线，不得把个人技术偏好冒充产品需求。
