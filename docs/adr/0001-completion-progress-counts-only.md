# 完成度只做计数，不做父项递归百分比

**状态**：已接受（2026-09-11）

背景：上游 v1.0（`docs/task-space-design/sources/upstream-tip-tip/WORKITEM_RELATIONS_REVIEW.md:76-92`）定义了等权递归百分比与 N/A 语义；但更高权威的 v1.2（`WORKITEM_SINGLE_USER_V11.md:24,264,478`）三次禁止「用子项数量生成父项完成百分比」，只允许计数呈现；本仓救援契约又要求父子聚合「另行定义可审计的聚合规则并提交合同修订」（`docs/task-space-design/recovered/pxii-rescue-2026-09-01/contract.md:262,281`）。

决定：P0 只做计数 —— 父项展示「已完成 X / 有效共 Y」，取消项从分母排除并单独计为「范围已取消」；**不实现父项百分比，不引入 `progressRatio` / 递归百分比字段**。N/A 保留为边界语义：有效直接子项为 0 时分母为空，具体边界与呈现见 ADR-0002。

考虑过的替代方案：(b) 计数 + 百分比 —— 需先完成合同修订（可审计聚合规则），属独立立项；(c) 维持现状 —— 不解决「父项是空壳容器」。

后果：百分比若将来要做，必须先走合同修订；以百分比为前提的信号（如 `hasProgressAnomaly`）在其之前不可用。
